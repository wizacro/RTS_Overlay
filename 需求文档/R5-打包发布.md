# R5 需求文档：打包 EXE 并发布 GitHub Release

> 状态：**待用户确认（G1）**
> 基于调研：2026-09-27，仓库版本 `fbe53aa`（R1-R4 已完成，未推送的 R4 一并随本次发布推送）

## 1. 调研结论

**打包机制**（`python/utilities/prepare_release.py`）：用 Nuitka 把每个游戏的 main_*.py 编译为独立 EXE（--standalone + pyqt5 插件），附带素材（docs/assets）、文档（Readme/Changelog/LICENSE/version.json）打包为 `{游戏}_overlay.zip`。上游 release 即为这些 zip（命名如 `aoe2_overlay.zip`）。

**环境要求**（关键）：
- 锁定的 `nuitka==1.0.6`（2022 年）**不支持本机 Python 3.13** → 必须新建 **Python 3.8 conda 环境**（与 README 建议一致，顺带解决 pynput 快捷键兼容问题）
- Nuitka 需要 C 编译器：本机未确认有 MSVC → 使用 Nuitka 自动下载的 MinGW64（约 100-200MB 下载）
- 脚本本身不含 nuitka 依赖 → 需在 3.8 环境中额外安装 `nuitka==1.0.6` + `orderedset==2.0.3`

**发布机制**：用已保存的 GitHub 凭据调 API 在 `wizacro/RTS_Overlay` 创建 Release（tag `v2.15.0-cn.1`）并上传 zip 资产，无需网页操作。

## 2. 实施步骤

1. `conda create -n rts_overlay python=3.8 -y` 建环境
2. 环境内安装：`pip install -r requirements.txt nuitka==1.0.6 orderedset==2.0.3`
3. `prepare_release.py` 微调：nuitka 命令追加 `--assume-yes-for-downloads --mingw64`（自动确认 MinGW 下载，避免交互卡住；属 fork 小改进）
4. 后台运行打包（在 3.8 环境、utilities 目录下）→ 产出各游戏 zip
5. 校验 zip 结构（exe 存在、素材目录齐全）
6. `git push`（先推送 R4 等）→ GitHub API 创建 Release `v2.15.0-cn.1`（中文说明）并上传 zip
7. 更新 README"EXE 版"小节：本 fork 现已提供**新界面中文 EXE** 下载

## 3. 资源与风险

| 项 | 评估 |
|----|------|
| 编译时长 | 每个游戏约 5-15 分钟（首次含编译器下载与 PyQt5 全量编译更久），5 个游戏总计可能 30-90 分钟 |
| 磁盘占用 | 约 2-4GB（编译中间文件，脚本完成后自动清理） |
| 兼容性 | Python 3.8 + PyQt5 5.15.7 + nuitka 1.0.6 = 上游验证过的组合，风险低 |
| 产物验证 | 打包后仅能验证 zip 结构与 EXE 启动（EXE 界面效果需你实机确认） |

## 3.1 发布后调整（2026-09-27，二次打包）

- **布局调整（用户需求）**：EXE 改放压缩包**根目录**（不再套 overlay 子文件夹），docs 素材随根目录；配套修改了素材目录解析（优先启动器旁 docs，回退上一级）。
- **配置便携化（用户需求）**：流程与设置默认保存在工具目录 `local_config/`（不再写系统 AppData）；首次运行自动复制旧 AppData 配置迁移（复制不移动，原数据保留）。
- 二次打包后**替换**了 Release 的旧 aoe2_overlay.zip 资产（旧包为旧行为构建，已被取代）。
