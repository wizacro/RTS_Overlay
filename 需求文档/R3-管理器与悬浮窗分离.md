## 1. 背景与目标

**现状痛点**：单置顶悬浮窗在"配置面板"和"建造顺序面板"之间循环切换，没有线性流程——初次使用不知道哪里导入、哪里展示、按钮都是小图标。

**目标**：拆成两个窗口，形成"**导入 → 选择 → 开启悬浮窗 → 进游戏用快捷键**"的线性流程：

- **管理器**：普通窗口（不置顶、带标题栏），承载全部管理功能
- **悬浮窗**：置顶、无边框、纯展示 + 整窗拖动，无任何按钮

游戏内的操作方式不变：全局快捷键推进步骤/控制计时器（现有机制原样保留）。

## 2. 界面设计

### 2.1 管理器

```
┌─ RTS Overlay 管理器 ─────────────────────────────┐
│ ① 导入建造顺序 → ② 选择与配置 → ③ 开启悬浮窗  [?帮助]│ ← 常驻指引条
├──────────────────────────────────────────────────┤
│ 【导入】  展示                                     │ ← 标签页
│                                                    │
│ 导入页：                                           │
│   ┌────────────────────────────────────────────┐  │
│   │ 在此粘贴建造顺序 JSON 文本…（内嵌大文本框）  │  │
│   └────────────────────────────────────────────┘  │
│   [导入并保存]   [打开建造顺序文件夹]               │
│   [打开 rts-overlay.github.io]                     │
│                                                    │
│ 底部维护栏：[保存设置] [打开设置文件夹] [退出]      │
└──────────────────────────────────────────────────┘

展示页：
│ 阵营/文明: [图标下拉▾]   搜索: [关键词或空格______] │
│ ┌──────────────────────────────────────────────┐ │
│ │ • 直城骑士        • 开局双TC       （结果列表）│ │
│ └──────────────────────────────────────────────┘ │
│ 悬浮窗: [ ● 开启悬浮窗 ]   状态: [ 游戏前·布置 | 游戏中 ]│
│ 外观:  背景色[■]  不透明度[────●──] 字号[11p▾] 缩放[100%▾] │
│ 展示控制: [⏮ 上一步] [⏭ 下一步] [⏱ 开始/停止] [↺ 归零] │
│          游戏内快捷键: Alt+' 下一步 · Alt+E 显示/隐藏 …  │
```

- **指引条**：三步状态自动检测——已导入建造顺序 ①打✓、已选中 ②打✓、悬浮窗已开启 ③打✓；点击各步直达对应区域
- **导入页**：把现有"粘贴建造顺序"弹窗的内容平移为页面内嵌（粘贴框 + 原有三个按钮）
- **展示页**：
  - 选择区 = 现有配置面板的阵营筛选 + 模糊搜索 + 结果列表（复用现有行渲染组件，视觉一致）
  - 悬浮窗开关 = 新增"开启/关闭悬浮窗"按钮
  - 外观区 = 现有字号/缩放下拉 + **新暴露**的背景色、不透明度控件（目前 EXE 版只能手改 JSON，改完即时生效）
  - 展示控制 = 现有建造顺序面板的 4 个按钮移入 + 快捷键速查（按钮进了管理器，游戏内靠快捷键，速查表放显眼处）
- **底部维护栏** = 现有保存设置/打开设置文件夹/退出按钮的去处

### 2.2 悬浮窗（改造后：双状态设计）

悬浮窗保留原工具的"双面板"状态机制，但两种状态都不再承载配置功能。**状态由管理器切换**：

**状态一：游戏前（布置模式）** —— 可整窗拖动，按钮可点击（进游戏前提前测试流程）
```
┌────────────────────────────────┐
│ [⏱] [⏮]  ⛏20 🪵4 🍖6  ⏱0:00 [⏭]│
│ 封建快攻                        │
│ ① 6人吃羊                      │
│ ② 4人伐木 → …                  │
└────────────────────────────────┘
置顶 · 左键按住任意位置拖动 · 按钮：开始/停止计时、上一步、下一步
```

**状态二：游戏时（游戏模式）** —— 禁止拖动，同样的三个按钮可点击
```
┌────────────────────────────────┐
│ [⏱] [⏮]  ⛏20 🪵4 🍖6  ⏱0:00 [⏭]│ ← 仅这三个按钮可点击
│ 封建快攻                        │
│ ① 6人吃羊                      │
│ ② 4人伐木 → …                  │
└────────────────────────────────┘
置顶 · 不可拖动 · 其余区域点击穿透到游戏（沿用原建造顺序面板机制）
```

- 两状态的按钮完全相同：开始/停止计时（start_stop）、上一步（previous）、下一步（next）；**归零按钮仅在管理器展示控制中**
- 布置模式可拖动 = 玩家进游戏前可提前测试/查看流程；游戏模式不可拖动 = 防误拖
- 点击穿透机制沿用原工具现成实现（`WA_TransparentForMouseEvents` 按状态切换，按钮子控件保持可点击）
- 保留：位置记忆、显示/隐藏快捷键、步骤/计时快捷键、计时器、"无建造顺序"提示
- 移除：全部配置类按钮与面板、粘贴弹窗入口

### 2.3 启动、关闭与状态切换行为（默认方案）

- 启动：只出现管理器，悬浮窗默认隐藏——对齐"先导入再展示"的线性流程（第③步由用户主动开启）
- 悬浮窗开启后默认进入**游戏前（布置模式）**；由管理器展示页的"状态"切换控件切到**游戏时（游戏模式）**，也可切回
- 原工具的 next_panel 快捷键顺延为"切换悬浮窗状态"快捷键（保留肌肉记忆，可不改用）
- 关闭管理器 = 退出整个程序（悬浮窗一并关闭）；最小化管理器不影响悬浮窗
- 快捷键配置窗口照旧（父窗口改为管理器）

## 3. 架构改动方案

| 现有组件（单窗内） | 去向 |
|---|---|
| BO 显示列表 / 资源行 / 注释 / 步骤推进 / 计时器 | 悬浮窗 |
| 全局快捷键、鼠标监听、拖动、位置记忆、显示/隐藏 | 悬浮窗 |
| 配置面板（搜索/筛选/字号/缩放/按钮排） | 管理器·展示页 / 底部栏 |
| 粘贴导入弹窗 | 管理器·导入页（内嵌） |
| 快捷键配置窗口 | 不变（父窗口改为管理器） |
| 设置 JSON | 向后兼容，新增管理器几何/悬浮窗偏好字段 |

- **新文件** `python/common/manager_window.py`（管理器窗口）
- **改造** `rts_overlay.py`：移除配置面板 UI，瘦身为**双状态悬浮窗**——原工具的 CONFIG/BO 双面板切换机制（`selected_panel` + `WA_TransparentForMouseEvents` 点击穿透）原样保留复用：布置模式 ≈ 原 CONFIG 面板的拖动行为（去掉配置控件）、游戏模式 ≈ 原建造顺序面板（去掉计时器按钮以外的旧元素）。**状态机制是现成的，这是本次改版风险最大的部分反而变得最稳**
- **`main_*.py`**：创建两窗；现有 QTimer 定时器机制不变
- **跨窗口**：管理器持有悬浮窗引用直接调用（同进程）：切换状态、开关悬浮窗、选择建造顺序、改外观后调 `overlay.reload()` 双窗刷新
- 汉化：新增 UI 文案全部走 `chinese_locale.py` 字典（机制现成）

**规模评估**：这是迄今最大的一次改动——预计新增管理器 600-900 行、rts_overlay.py 删减约 400 行配置面板部分。上游同步冲突面将显著增大（一次性成本，随合并流程消化）。
