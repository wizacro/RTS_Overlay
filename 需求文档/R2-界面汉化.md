## 3. 改动方案（集中式运行时映射层）

**核心思路**：不改散落各处的界面字符串，而是新建一个翻译模块，在程序启动时对 Qt 的"文字出口"安装映射钩子——凡是字典里精确命中的英文串显示中文，未命中的原样通过。

**新增文件（1 个）**：`python/common/chinese_locale.py`
- `TRANSLATIONS` 字典：界面英文 → 中文（预计 200-250 条）
- `t(s)`：精确匹配返回译文，否则原样返回——**任何遗漏都只是显示英文，绝不会破坏功能**
- `install()`：对以下 Qt 出口安装钩子（幂等）：`setText`（QLabel/QPushButton/QCheckBox/QGroupBox/QLineEdit/QMessageBox 等）、`setWindowTitle`、`setToolTip`、`setPlaceholderText`、`addItem`/`addItems`（QComboBox）、QPushButton/QLabel/QCheckBox/QGroupBox 构造函数中的文本参数

**修改文件（最小化，共约 15 行）**：
- 5 个 `main_*.py`：各插入 2 行（导入 + 安装钩子，在窗口创建前）
- `python/common/rts_overlay.py`：约 10 处动态消息（f-string 拼接的弹窗提示、`Step: 1/15` 步骤计数）无法靠字典精确命中，在这些调用点用 `t()` 包装静态部分（清单见 3.1）

**3.1 动态消息处理清单**：粘贴建造顺序对话框的全部提示（约 10 条，如 "Invalid build order format"、"Build order saved as: xxx"——名称部分保持动态拼接）、步骤计数 `Step: x/y` → `步骤: x/y`、计时器相关动态文本。

**为什么不用"就地替换全部字符串"**：500+ 处散改会让每次同步上游都产生大面积冲突，且手工改动面越大出错概率越高；集中式方案改动集中、可审查、遗漏安全降级、以后上游合并几乎无冲突。

## 4. 风险评估

| 风险 | 等级 | 对策 |

## 8. 实施记录

**落地文件**：
1. 新增 `python/common/chinese_locale.py`：翻译字典（约 40 组键值）+ `t()` 精确映射函数 + `install()` 钩子（覆盖 setText/setWindowTitle/setToolTip/setPlaceholderText/addItem/addItems 及 QLabel/QPushButton/QCheckBox/QGroupBox 等构造函数文本参数）

3. `rts_overlay.py`：导入 `t()` + 5 处动态消息包装（4 条弹窗提示 + 步骤计数）
4. `hotkeys_window.py`：导入 `t()` + 快捷键说明长文本包装
5. 新增 `需求文档/R2-冒烟测试.py`（子进程冒烟测试 + 覆盖率扫描）

**实施中发现并处理的问题**：
1. PyQt5 中 QAction 位于 QtWidgets 而非 QtGui（Qt6 才在 QtGui）→ 已修正；
2. 冒烟测试在同一进程连续构建多个完整悬浮窗时出现段错误 → 对照实验证明**不加钩子同样段错误**，属"同进程多窗口 + 全局监听器堆积"的测试假象，非汉化代码缺陷；测试已改为每游戏独立子进程（与真实使用一致），全部通过。

**第二轮补漏（2026-09-26，来自用户实机验收反馈）**：
- 用户截图发现 2 处漏译（"add/edit build orders in BO folder" 悬浮提示、"Select build order with search bar." 提示文本）。
- 根因：这些字符串经**辅助函数关键字参数**（TwinHoverButton 的 `tooltip=`）和**方法返回值**（`get_no_build_order_text`）传递，不经过调用点常量，首轮 AST 扫描盲区。
- 全量排查后补入字典 18 条：10 个动作按钮 tooltip、4 个建造顺序箭头按钮 tooltip（变量三元赋值）、4 条"无建造顺序"提示。
- 覆盖率检查器同步新增 3 条规则（tooltip/text/title 关键字参数、tooltip/title 变量赋值含三元分支、return 界面文案），全部报告 0 遗漏；5 游戏冒烟测试复跑通过。

**重要环境发现（与汉化无关，但影响 Python 源码方式使用）**：项目锁定的 `pynput==1.7.7`（2022 年发布）与 **Python 3.13 不兼容**——全局快捷键监听线程会反复报错。原项目 README 要求用 conda 创建 python=3.8 环境运行。本机 Anaconda base 为 3.13，暂无 3.8 环境。若实机验收时快捷键无效，请先按 README 创建 conda 3.8 环境（`conda create --name rts_overlay python=3.8`）或在需求文档中另立"依赖环境适配"需求。此问题在汉化前即存在，不属于本次改动引入。
